# نقل بيانات main إلى SQLite

الأداة تقرأ الملفات الثلاثة التي يحفظها `main` فعلاً، وتجهّز خطة وملف SQL ومشروع CLI منفصلاً. لا تسجّل الدخول، ولا تنشر، ولا تنفّذ النقل أثناء التحضير.

| المصدر | الوجهة | المحتوى |
| --- | --- | --- |
| `usage_limits.json` | `vinyl_users` | العدد، بداية نافذة الاستخدام، انتهاء الاشتراك وخط أساسه |
| `_whitelist` داخل ملف الاستخدام | `vinyl_whitelist` | الآيدي، الملاحظة ووقت الإضافة |
| `_premium_colors` داخل ملف الاستخدام | `vinyl_paid_colors` | الأقراص المدفوعة |
| `custom_texts.json` | `vinyl_custom_texts` | العربية، `EN::`، HTML، Rich Message وصورة قائمة الأقراص |
| `help_message.json` | `vinyl_help_docs` | المنشور والمسودات، البلوكات، RTL والأزرار |

في `main`، اللغة والسرعة واختيار القرص محفوظة في ذاكرة Python، وليست ضمن ملفات JSON هذه. لا يمكن استرجاع تلك التفضيلات من الملفات؛ الحسابات المنقولة تبدأ بالقيم الافتراضية. بيانات المالك المجهول `0` تُحفظ إن وجدت، لكن لا تُعامل كحساب تليكرام صالح للقائمة البيضاء أو مسودة المطور.

## التحضير والمراجعة

```bash
npm run prepare:legacy-import -- /path/to/main/data /tmp/vinyl-legacy-import
```

يجب أن يكون مسار الإخراج جديداً. يطبع الأمر أسماء الملفات الموجودة/المفقودة وعدد السجلات فقط؛ لا يطبع بيانات المستخدمين. الملفات المولّدة خاصة بصلاحية `600`، داخل مجلد `700`، ومعها `.gitignore` يمنع رفعها بالخطأ.

راجع `plan.json` محلياً. يحتوي `import.sql` على نفس الإدخالات ضمن transaction للاختبار في SQLite محلية بالجداول الحالية. لا يحتاج تحويل البيانات إلى Node أو ملفات داخل runtime: مشروع CLI يتضمن البيانات كوحدة JavaScript ويستخدم `sdk/db`.

النقل يستخدم **INSERT OR IGNORE**: لا يغيّر أي سجل موجود. كرر المحاولة دون مضاعفة البيانات. إذا تعاملت حسابات مع البوت قبل النقل فقد تكون صفوفها موجودة بالفعل؛ ستُتخطى، بما فيها بيانات استخدامها واشتراكها القديم. الأفضل الاختبار على جداول جديدة قبل بدء محادثات المستخدمين. لا يوجد وضع overwrite مخفي.

أُضيف `premium_base_until` حتى تتراكم الإيصالات اللاحقة فوق مدة الاشتراك المنقولة، دون تمديد متكرر عند إعادة التسليم أو القراءة. قراءة سجل الإيصالات تصلح تحديث الاشتراك الذي انقطع، والتحديث لا ينقص انتهاء أحدث إذا انتهت عملية قديمة متأخرة.

## تشغيل نسخة اختبار

طبّق schema الحالية على البوت التجريبي الذي تختاره أولاً. من المجلد المولّد:

```bash
cd /tmp/vinyl-legacy-import
npm install
npx tgcloud login
npx tgcloud status
npx tgcloud run handlers/message '{"start":0,"limit":100}'
```

تابع باستعمال `nextStart` حتى تصبح `complete: true`. الحد 100 عملية لكل استدعاء. إذا فشل الاستدعاء كرره من نفس `start`؛ الإدخالات السابقة تُتخطى. **دفعة النقل على SDK ليست transaction واحدة**، لذا لا تفترض الرجوع عن الإدخالات السابقة عند انقطاعها. بعد كل دفعة راجع `inserted` و`skipped`.

هذا handler مؤقت ينفّذ بواسطة CLI فقط. **لا تنشر مشروع النقل** ولا تحوله إلى endpoint عام. `tgcloud run` يرفع المصادر المحلية للاستدعاء المؤقت ولا يسجّل handler في البوت. ملفات الخطة تحتوي بيانات المستخدمين، وfile IDs للصور مرتبطة بالبوت الأصلي وقد لا تعمل في بوت مختلف.

اختُبر توليد الملفات والخطة وSQL والاستكمال والتكرار محلياً على SQLite حقيقية. قبول المنصة للوحدات وحجمها ودفعات النقل يحتاج تجربة Telegram الفعلية. لم يُنقل أي سجل إنتاجي في هذا العمل.
