# دليل اختبار نسخة السيرفليس

هذا الفرع جاهز لاختبار الرسائل والمنطق على Telegram Serverless CLI **0.2.0**. محرك الفيديو غير مكتمل؛ تأكيد المعاينة أو الإنشاء يعرض رسالة واضحة ويُبقي الطلب ولا يخصم الاستخدام. الاشتراكات الجديدة مغلقة.

## إعداد محلي

استخدم Node.js **22.13 أو أحدث** للاختبارات؛ Node وSQLite هنا أدوات اختبار محلية، وليسا اعتماديات للبوت على Telegram.

```bash
git checkout serverless
npm ci --ignore-scripts
npm run check
```

اضبط `DEVELOPER_ID` في `tgcloud/lib/config.js` إلى آيدي حسابك الرقمي في تليكرام. القيمة الافتراضية `0` تغلق لوحة المطور. اترك `RENDERER_ENABLED: false`.

## ربط بيئة تليكرام التي ستختبر فيها

فعّل Serverless من BotFather للبوت المختار، ثم افتح CLI Access. استخدم **CLI access token** مع أمر login؛ هو مختلف عن توكن Bot API. لا تضع التوكن في Git أو ملفات الاختبار.

```bash
npx tgcloud login
npx tgcloud status
npx tgcloud diff
# فحص تحميل الوحدات، دون إرسال رسالة أو استعمال قاعدة البيانات:
npx tgcloud run handlers/message '{}'
```

بعد مراجعة الوحدات، نشر نسخة الاختبار وإنشاء جداولها هما خطوتان منفصلتان:

```bash
npx tgcloud push
npx tgcloud migrate --dry-run
npx tgcloud migrate
```

هذا التسليم لم ينفذ هذه الأوامر على أي بوت. عند تحديث قاعدة قديمة، راجع إضافة `mode` و`revision` إلى `vinyl_sessions`، و`rich_json` إلى `vinyl_custom_texts`، و`is_rtl` إلى `vinyl_help_docs`. البيانات القديمة لا تُحذف. لا توجد أداة نقل بيانات Python/JSON في هذا التسليم.

## اختبارات المحادثة

| الاختبار | النتيجة المطلوبة |
| --- | --- |
| `/start` وتبديل اللغة | نصوص الأصل بالعربية والإنكليزية وأزرار قابلة للعمل |
| التخصيص واللون والسرعة | 13 قالباً، 5 سرعات، وحفظ التفضيلات بعد استدعاء جديد |
| فتح قائمة ألوان بصورتها ثم الرجوع | تعديل caption للصورة والعودة إلى قائمة الإعدادات النصية |
| إرسال Audio ثم تخصيص | لون ← سرعة ← غلاف ← دقيقة عند الحاجة ← تأكيد |
| Audio بلا thumbnail ثم سريع | طلب الغلاف، استقبال الصورة، والإبقاء على الملف الصوتي الأصلي |
| تخطي الغلاف | يظهر فقط عندما توجد صورة أصلية |
| Audio أطول من 20 دقيقة | أزرار صفحات الدقائق، وحفظ الدقيقة الصحيحة |
| إلغاء في كل مرحلة أو `/cancel` بالخاص | حذف الجلسة وعدم خصم الاستخدام |
| الضغط على زر طلب قديم | رفضه دون تغيير الطلب الجديد |
| إرسال Audio نفسه كتحديث مكرر | لا يعيد ضبط الجلسة أو يرسل قائمة جديدة |
| انتهاء الجلسة بعد 10 دقائق | رسالة انتهاء، ولا يستمر الطلب القديم |
| ملف أكبر من 20 MiB أو Voice/Video/Document بالخاص | رسالة النوع/الحجم الأصلية |
| مجموعتان وطلب خاص لنفس الشخص | استقلال الجلسات؛ صورة المجموعة لا تعدّل الطلب الخاص |
| صورة داخل مجموعة | يجب الرد على رسالة طلب الغلاف، مع تحقق المالك أو المشرف |
| قناة | المشرف يتحكم بالأزرار؛ الغلاف ردّ على رسالة البوت بالقناة |
| معاينة أو إنشاء الفيديو | رسالة عدم التوفر؛ لا فيديو وهمي ولا خصم ولا فاتورة |

امنح البوت صلاحية إرسال الرسائل والصور في المجموعة/القناة، وصلاحيات الإدارة اللازمة لاستعلام عضوية المشرفين. اختبر فقدان تلك الصلاحيات أيضاً؛ فشل API يبقى خطأ فعلياً ولا يُسجّل نجاحاً.

## لوحة المطور والرسائل الغنية

| الاختبار | النتيجة المطلوبة |
| --- | --- |
| `/dev` من حساب المطور فقط | لوحة الأقراص، صورة القائمة، محرر النصوص، القائمة البيضاء، وحالة الأقراص المدفوعة |
| `/search كلمة` | البحث في أسماء النصوص وقيمها الحالية المعدلة، بالعربية والإنكليزية |
| `/edit MSG_START_HELP` أو `/edit MSG_START_HELP en` | حفظ مستقل ودائم لكل لغة |
| أزرار محرر النصوص | 108 نصوص عربية و92 إنكليزية، صفحات وتنقل ورجوع |
| `**عريض**`، كود، ووسم custom emoji | تنسيق محفوظ؛ رفض آيدي الإيموجي غير الرقمي |
| HTML مكسور | تليكرام يرفض رسالة التحقق؛ يبقى المحرر مفتوحاً ولا تُحفظ القيمة |
| Rich Message بها نص وصورة | حفظ البلوكات واتجاه RTL؛ إعادة إرسال أكبر photo file_id كـ input media |
| `/cancel_edit` أو زر رجوع | مسح عملية التحرير المعلقة |
| القائمة البيضاء: إضافة/إزالة وأكثر من 25 مستخدماً | استثناء الحدود، وإتاحة جميع المستخدمين بصفحات |
| `/help` من المطور | مسودة مستقلة، تعديل، أزرار URL، معاينة، حذف زر، ونشر |
| `/help` من مستخدم آخر | النسخة المنشورة فقط، دون أزرار التحرير |

تحقق خاصةً من قبول Telegram الحقيقي لبلوكات Rich Message، و`sendRichMessage`، و`editMessageText` مع `rich_message`، وأنماط الأزرار وcustom emoji. الاختبارات المحلية تستبدل SDK transport ولا تثبت قبول المنصة لهذه الطلبات.

## فحص قدرات محرك الفيديو

أنشئ مشروع فحص منفصلاً بمسار جديد:

```bash
npm run prepare:video-probe -- /tmp/vinyl-runtime-probe
cd /tmp/vinyl-runtime-probe
npm install
npx tgcloud login
npx tgcloud run handlers/message '{}'
```

لا يوجد push أو migrate لهذا الفحص. معالجه المؤقت يستدعي مكتبة diagnostics فقط؛ لا يرسل رسالة ولا يقرأ أغنية ولا يصل إلى قاعدة البيانات. النتيجة تكشف WebAssembly وCanvas وVideoEncoder/AudioEncoder ودعم إعدادات H.264/AAC. نجاح هذا الفحص وحده **ليس نجاح إنشاء فيديو**. Gate A يحتاج ملفاً متحركاً صالحاً وإرساله كفيديو نوت والتحقق من فكّه فعلياً.

## الدليل المتوفر الآن

نجح `npm run check`: **19 وحدة JavaScript و62 اختباراً محلياً**، تشمل اختبارات الأصل وواجهات الرسائل والسلوك مع SQLite حقيقية داخل سياقات JavaScript مستقلة. ملف `docs/video-engine/parity.md` يفرّق بين السلوك المثبت محلياً والاختبارات التي تحتاج Telegram. لم تُحسب نسبة اكتمال 95% على أساس مراجعة المصدر وحدها.
